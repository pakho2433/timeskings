# 🐻 乘法王：熊仔乘法跑酷 Times King Bear Race

以 3D 小熊為角色的網頁乘法跑酷遊戲，供 **1–4 名玩家**在同一房間競速。全程 **10 關**，每關固定有 **3 個答案平台**；玩家各自過關，完成全部關卡後再衝過終點線。

> 文件核對日期：2026 年 11 月 5 日。以 PR #6 的熊仔跑酷版本為基礎，同步修正已衝線玩家離線後的名次重複問題。下列規則已從程式碼核對，並通過單元測試及本機 HTTP／WebSocket 整合測試；手機／iPad 兼容性、雲端連線及課堂負載仍須按文末清單實機測試。

## 🎮 遊戲規則

1. 每個房間最多 **4 人**，亦可 **1 人練習**。伺服器在開賽時一次產生全房共用的 10 關題目。
2. 題目為 **1 至 9 × 1 至 9**的隨機乘法，例如 `7 × 8 = ?`；目前沒有指定乘數或難度的選單。
3. 每關有 **3 個數字互不重複的平台**：**1 個正確答案、2 個錯誤答案**。必須操控熊仔跑跳、踩上平台作答，沒有直接點選答案的按鈕。
4. 踩中本關正確平台後，即可繼續下一關，畫面題目隨自己的進度更新。**不用等待其他玩家答對。**
5. 踩錯平台會變紅並塌下；熊仔跌落後返回目前關卡的起點重試。跳空跌落亦會重生，不會被淘汰；已完成的關卡不必重答。跌落次數會記錄。
6. 支援 **二段跳**：第一次起跳後，在空中放開並再按一次跳躍按鈕；落地後重設跳躍次數。
7. **答完第 10 關並不代表完成比賽。**須繼續向前，跑過 `FINISH 終點`線，才會登記個人名次及完成時間。
8. 已衝線玩家會看到自己的名次並等待全場結算，其他玩家可繼續跑。當房間內所有仍在場的玩家均已衝線，才顯示結算畫面。

### 名次、時間及結算

- 衝線名次由伺服器按收到有效完成訊息的先後登記；不是按跌落次數或畫面顯示的秒數決定。網絡延遲可能影響非常接近的衝線次序。
- 未衝線時，畫面上的玩家次序依關卡進度、較少跌落次數，再按加入槽位排序，**並非連續追蹤跑道距離的正式名次**。
- 結算畫面列出名次、玩家暱稱、個人完成時間及跌落次數，另顯示全場時間與自己的跌落次數。時間以整秒記錄。
- 個人時間由全場開賽起計至該玩家衝線；全場時間由開賽起計至伺服器結算。
- 「再跑一次」會重新載入首頁，須重新建立或加入房間；不會直接保留原房間開下一局。

## 🏠 建立及加入比賽

1. 每位玩家用自己的手機或 iPad 開啟**同一個伺服器網址**。
2. 輸入暱稱（最多 12 字；課堂建議使用學號或簡短代號）。
3. 每組由一人按「🏟️ 建立比賽房間」，把系統產生的 **5 碼英文字母／數字代碼**告訴組員。
4. 其餘組員輸入代碼，按「🐻 加入比賽」。房間總人數包括建立者，最多 4 人。
5. 核對所有組員已出現在房間畫面後，再由一人按「▶ 開始熊仔跑酷！」。

**任何房內玩家都可以開賽，沒有只限房主的開始權限。**比賽開始或結束後，其他玩家都不能再加入該房間；遲到者須另開房間。最後一名玩家離開後，房間會被刪除。

目前沒有獨立的教師監察台或旁觀者模式。教師若以玩家身分加入，也會佔用一個名額。

## 📱 手機／iPad 操作教學

角色移動及跳躍只綁定觸控事件，**沒有鍵盤或滑鼠操控**。裝置瀏覽器須能執行 JavaScript、WebGL 及 WebSocket；實際兼容性請先用學校裝置測試。建議先把裝置轉為**橫向**再開始，讓題目和跑道較易看清；直向亦有專用版面樣式，但不同螢幕仍須驗收。

### 給小學生的「看、算、移、跳、衝」

1. **看題目**：看看上方是第幾關，讀出乘法算式。
2. **算答案**：例如 `6 × 7`，先想好答案是 `42`，再找有 `42` 的平台。
3. **移動熊仔**：左手拇指按住左下方圓形搖桿，向上推是向前跑，向下推是後退，向左／右推可調整位置；放開便停止水平移動。
4. **跳上平台**：左手繼續推搖桿，右手拇指點右下方 `⬆️` 跳躍。需要二段跳時，放開右手，再點一次；一直按住不會自動連跳。
5. **跌落再試**：等熊仔返回本關起點，重新看題和調整方向；不必從第一關重來。
6. **最後要衝線**：看到「最後直路／衝過終點！」後，繼續向前跑過終點，才算完成。

教師可先安排單人試玩，示範「左手移動、右手跳躍」的雙手操作，再分組競速。遊戲同時涉及乘法及跑跳操控，宜讓學生先熟習操作。

### 遊玩期間

- 保持遊戲頁面在前景，避免鎖屏、切換 App 或重新整理；這些操作可能中斷連線。
- 程式會嘗試重新連線，但**沒有恢復原玩家身分、房間或進度的機制**。「已重新連線」不代表能接續原局。
- 若斷線後不能繼續，重新整理回首頁；已開賽的房間不能重新加入，請由教師安排另開一局。
- 有人離線後，其餘玩家仍可繼續；離線玩家會從房間移除，其結果不會保留在該房間的最終名單。
- 已登記的衝線名次不會因玩家離線而重用；例如第 1 名離線後，其他玩家仍保留第 2、3、4 名，結算名單可能有名次空缺。

## 🚀 本機安裝與啟動

### 需求

- Node.js 及 npm。`package.json` 宣告最低版本為 **Node.js 16.0.0**；現有 GitHub Actions 使用 **Node.js 20**。新環境建議選仍獲支援的 Node.js LTS，並執行測試核對。
- 可使用觸控的手機／iPad；多人遊戲須連至同一個遊戲伺服器。

### 下載及安裝

```bash
git clone https://github.com/pakho2433/timeskings.git
cd timeskings
npm install
```

### 啟動伺服器

```bash
npm start
```

預設網址為 `http://localhost:3000`；如有設定 `PORT` 環境變數，伺服器會使用該連接埠。

手機／iPad 在同一區域網絡內，可開啟電腦的區域網絡 IP，例如 `http://192.168.1.100:3000`（請換成實際 IP 及連接埠）。**不要在學生裝置輸入 `localhost`**，它會指向學生自己的裝置。電腦須保持開機、伺服器須持續運行，並允許該連接埠的連線；學校 Wi-Fi 若設有裝置隔離，須由資訊科技人員協助確認。

電腦瀏覽器可檢查首頁是否載入；一般鍵盤／滑鼠無法操控熊仔。

### 開發模式（檔案變更時自動重啟）

```bash
npm run dev
```

開發模式重啟伺服器亦會清除記憶體內的房間，請勿在同學比賽期間修改程式。

### 測試

```bash
npm test
```

現有測試涵蓋題目生成、三選一及排行榜排序，另會啟動本機伺服器，以 HTTP 及 5 條 WebSocket 連線驗證四人上限、共同題目、獨立過關、衝線條件、離線後不重複名次、全場結算及單人比賽。GitHub Actions 亦會執行這些測試及 JavaScript 語法檢查。這些檢查**不等同**已完成實際觸控、3D 碰撞、雲端多人連線或 Render 課堂負載測試。

## ☁️ Render 雲端部署

專案需要可執行 Node.js 及接受 WebSocket 連線的 **Web Service**；只部署 `public/` 靜態檔案不能提供房間及多人同步。

### 目前 `render.yaml` 設定

| 項目 | 設定 |
| --- | --- |
| 服務類型／名稱 | `web`／`timeskings` |
| 執行環境 | `node` |
| 服務方案 | `free` |
| 地區 | `singapore` |
| 建置指令 | `npm install --omit=dev` |
| 啟動指令 | `npm start` |
| 健康檢查路徑 | `/` |
| 自動部署 | `autoDeployTrigger: commit` |
| 環境變數 | `NODE_ENV=production` |

以上是版本庫設定，**不代表已核對現有 Render 服務的實際設定或運行狀態**。YAML 沒有指定 Node.js 版本或服務分支；建立服務時須確認版本，並選擇 `main`。

### 部署步驟

1. 登入 [Render Dashboard](https://dashboard.render.com/)，選擇 **New → Blueprint**。
2. 連接 GitHub 專案 `pakho2433/timeskings`；如使用自己的副本，選擇相應版本庫。
3. 選擇 **`main`** 分支，Blueprint 路徑使用根目錄的 **`render.yaml`**。
4. 核對上述設定及所選方案，再確認建立／部署 Blueprint。
5. 等待部署成功，在服務頁取得實際的 `https://…onrender.com` 網址。
6. 用兩部或以上觸控裝置開啟同一網址，測試建立房間、加入及完整衝線流程，再分享給全班。

伺服器讀取 Render 提供的 `PORT`；HTTP 與 WebSocket 共用同一伺服器。前端會依目前頁面網址自動選用 `https` 對應的 `wss://` 或 `http` 對應的 `ws://`，毋須手填 WebSocket 網址。

`autoDeployTrigger: commit` 表示所連服務分支收到新提交便可觸發部署，並非等待測試通過才部署。部署步驟及欄位以 [Render Blueprint 文件](https://render.com/docs/infrastructure-as-code)及 [YAML 參考](https://render.com/docs/blueprint-spec)為準。

## 🧑‍🏫 教師使用 Render 免費伺服器的注意事項

### 課前準備

- 每組最多 4 人，每位實際玩家使用一部裝置；可開多個房間，但**全班同時使用的容量未經負載測試**。
- 建議上課前 **5–10 分鐘**先開網址並試建房間，再用學生裝置試連；這是課堂準備建議，不是喚醒時間保證。若顯示服務啟動頁，先等候服務就緒，再重新整理重試。
- 檢查學校網絡可存取遊戲 HTTPS／WebSocket，以及 `cdnjs.cloudflare.com` 和備用 `cdn.jsdelivr.net`。Three.js 由這兩個外部 CDN 載入；只開通遊戲網址仍可能無法顯示 3D 畫面。
- 確認 Render Dashboard 的服務狀態及用量，備妥紙本乘法練習或本機伺服器作活動後備。

### 休眠、重新啟動及資料

- 按 Render 免費方案文件，約 **15 分鐘沒有收到 HTTP 請求或現有連線的 WebSocket 訊息**便會休眠；下一次請求／新連線會喚醒，通常約需 **1 分鐘**。正在收取遊戲訊息不等於閒置，但只把等待頁開着不能保證服務一直運行。
- 房間、進度、完成時間及名次只存於 Node.js 程序的**記憶體**，沒有資料庫或成績匯出功能。服務休眠、重新啟動或重新部署後，原房間及結果均無法恢復；須重新建立房間、分發新代碼。
- 免費服務也可能被平台重新啟動。需要保留結果時，請在學生離開或按「再跑一次」前記錄／截圖；上課期間避免提交至自動部署所連分支或手動重新部署。
- 免費執行時數為每個工作區每月共用 **750 小時**；耗盡後免費服務會暫停至下月。另有流量及建置用量限制，課前請查看 Dashboard。
- 改用付費運算方案可免除免費方案的閒置休眠，但**不會自動加入進度保存或斷線續玩**；目前程式在付費服務重新啟動時仍會失去記憶體資料。

平台條款可能更新，請參閱 [Render 免費方案說明](https://render.com/docs/free)及 [WebSocket 文件](https://render.com/docs/websocket)。

## ✅ 已確認範圍及實機驗收清單

**已從程式碼確認：**1–4 人房間、全房相同的 10 關、每關三選一、玩家獨立過關、錯台塌陷／跌落重生、二段跳、完成 10 關後衝線登記、全場完成後結算，以及上述部署設定。

**仍須在實際裝置及學校網絡測試：**

- [ ] 學校使用的 iPhone／iPad Safari 及其他學生裝置，能載入 WebGL 畫面和外部 CDN。
- [ ] 左手搖桿與右手跳躍能同時操作；二段跳、放手停止及觸控中斷後均正常。
- [ ] 橫向／直向下，題目、玩家進度和控制鈕清晰，沒有重疊或被瀏海／瀏覽器工具列遮擋。
- [ ] 四部裝置同房時，錯答重生、各自過關及位置同步正常。
- [ ] 答完第 10 關尚未衝線不登記名次；衝線後名次、時間及全場結算符合預期。
- [ ] 玩家中途離線、已衝線玩家離線，以及網絡中斷後的畫面和名次處理；名次不重複已有本機 WebSocket 回歸測試，仍須核對實際裝置顯示。
- [ ] 免費服務休眠後的喚醒、重新建房，以及全班多房同時使用的延遲與穩定性。
